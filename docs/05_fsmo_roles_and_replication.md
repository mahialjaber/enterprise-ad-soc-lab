# FSMO Roles Architecture & AD Replication

Active Directory uses **multi-master replication** for most updates (such as creating an account or changing an attribute), meaning changes can occur on any DC and propagate to all partners. However, five specific directory operations require a single authoritative master to avoid race conditions and database corruption. These are known as **Flexible Single Master Operations (FSMO)** roles.

---

## 1. The 5 FSMO Roles Detailed

| Role Name | Scope | Default Holder | Critical Functionality | Failure Impact |
| :--- | :---: | :---: | :--- | :--- |
| **Schema Master** | Forest | Forest Root DC | Controls all additions, modifications, and updates to object classes and attributes across the entire forest. | Cannot install Exchange, upgrade OS schema, or modify AD schema. Normal operations unaffected. |
| **Domain Naming Master** | Forest | Forest Root DC | Authoritative for adding, removing, or renaming domains and directory partitions in the forest. | Cannot add new domains or partitions. Normal operations unaffected. |
| **PDC Emulator** | Domain | Forest Root DC | Authoritative NTP time server, processes immediate password changes, handles account lockouts, master browser. | Immediate authentication inconsistencies, password sync latency, Kerberos clock skew failures. |
| **RID Master** | Domain | Forest Root DC | Allocates pools of 500 Relative IDs (RIDs) to each DC. When objects are created, SIDs are generated by appending a RID to the Domain SID. | DCs can create objects until their local 500-RID pool is exhausted. Once exhausted, object creation halts. |
| **Infrastructure Master** | Domain | Forest Root DC | Responsible for updating cross-domain object references (translating cross-domain GUIDs to SIDs). | In single-domain environments: No impact. In multi-domain setups: Group membership across domains fails to resolve. |

---

## 2. Replication Architecture

* **Intra-Site Replication:** High-bandwidth, uncompressed RPC-over-IP (`RPC/IP`) with immediate change notifications.
* **Inter-Site Replication:** Compressed replication traffic scheduled across site links (cost-based topology).
* **Knowledge Consistency Checker (KCC):** Automated background process running on all DCs that dynamically builds and heals the replication ring topology.

## 3. Replication Health Playbook

```cmd
:: 1. Display replication partners and last synchronization timestamp
repadmin /showrepl

:: 2. Summary dashboard of DC health and replication errors
repadmin /replsummary

:: 3. Force immediate forest-wide synchronization across all naming contexts
repadmin /syncall /AdeP

:: 4. Verify directory replication service consistency
dcdiag /test:replications
```
